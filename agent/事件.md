# SlimefunHelper 事件通道文档

> 对应代码:`src/main/java/me/matl114/events/Listener.java`、`RenderListener.java`
> 版本:**Minecraft 26.1.2 / 26.2**(mojmap 官方名)。事件通道本身两版一致,
> 但通道**载荷里用到的原版 API** 有差异,见 `总述.md` 的「26.1.2 与 26.2 的 API 差异」。
> 表里的"通道"列就是 **getter 名**(Lombok `@Getter` 对字段 `postGameTick` 生成 `getPostGameTick()`)。
> 直接访问静态字段是禁止的,必须走 getter。

## 1. Event 对象

所有回调收到的是 `Event<T>`:

| 成员 | 类型 | 说明 |
|------|------|------|
| `context()` | `T` | 事件主体(如攻击事件的 `HitResult`) |
| `context(T val)` | `Event<T>` | 修改事件主体;通道不允许修改时抛 `IllegalArgumentException` |
| `isCancelled()` | `boolean` | 是否已被取消 |
| `cancel()` | `Event<T>` | 取消事件;通道不允许取消时抛 `IllegalArgumentException` |
| `getArgs(int idx)` | `W` | 取额外参数(按 `@ExtraArgs` 声明顺序) |
| `canCancel` | `public final boolean` | **公有只读字段,不是方法** |
| `canModifyContext` | `public final boolean` | **公有只读字段,不是方法** |

> 这两个 `canXxx` 是 `Event` 上的 `public final` 字段(见 `Event.java`),
> 所以写 `event.canCancel`,不要写 `event.canCancel()`。
> 通道是否可取消/可修改由通道定义处的注解(`@Cancelable` / `@Modifiable`,可带 `optional = true`)固定,
> 处理器里不要试图改这些标志。

**使用示例**:

```java
private void onGameRender(Event<GameRenderer> event) {
    DeltaTracker tickCounter = event.getArgs(0);
    boolean isRenderWorld = event.getArgs(1);

    if (someCondition && event.canCancel) {
        event.cancel();
    }
}

private void onChatSend(Event<String> event) {
    if (event.canModifyContext) {
        event.context("[Prefix] " + event.context());
    }
}
```

## 2. 通道访问与注册规范

| 类 | 正确方式 | 错误方式 |
|---|----------|----------|
| `Listener` | `Listener.getPostGameTick()` | `Listener.postGameTick` |
| `Listener` | `Listener.getPacketPoint()` | `Listener.packetPoint` |
| `RenderListener` | `RenderListener.getRender3DEvent()` | `RenderListener.render3DEvent` |

```java
@Override
public void registerAll() {
    super.registerAll();

    // 基础事件
    registerListener(Listener.getPostGameTick(), this::onTick);
    registerListener(RenderListener.getRender3DEvent(), this::onRenderWorld);

    // 精确网络包事件(避免 getPacketSendPoint / getPacketAcceptPoint 收全量包)
    registerListener(Listener.getPacketPoint().getChannel(ServerboundUseItemOnPacket.class), this::onUseItemOn);
    registerListener(Listener.getPacketPreHandlePoint().getChannel(ClientboundStartConfigurationPacket.class), this::onReconfig);
    registerListener(Listener.getPacketPostHandlePoint().getChannel(ClientboundDisconnectPacket.class), this::onDisconnect);

    // 带优先级(数值越大越先执行)
    registerListener(Listener.getAttackAction(), this::onAttack, -999);
}
```

- 处理器签名:`Consumer<Event<T>>` 或 `Predicate<Event<T>>`(`Predicate` 返回 false 等价于 `cancel()`)。
- 分发通道(`EventChannelDispatcher` / `PacketEventChannel`)用 `getChannel(...)` 取子通道。

## 6. 网络包事件

| 通道 | 类型 | 特性 | 取子通道 |
|------|------|------|----------|
| `getPacketPoint()` | `PacketEventChannel` | Cancelable, Modifiable, Args: `Connection`, `@Dispatch(by = "type and side")` | `.getChannel(XXXPacket.class)` |
| `getPacketPreHandlePoint()` | `PacketEventChannel` | Cancelable, Args: `PacketListener`, `@Dispatch(by = "type")` | `.getChannel(XXXPacket.class)` |
| `getPacketPostHandlePoint()` | `PacketEventChannel` | Broadcast, Args: `PacketListener`, `@Dispatch(by = "type")` | `.getChannel(XXXPacket.class)` |
| `getPacketPostSendPoint()` | `PacketEventChannel` | Args: `Connection` | 一般直接用 |
| `getPacketPostScheduleSendPoint()` | `PacketEventChannel` | Args: `Connection` | 包进入发送队列后 |
| `getPacketAcceptPoint()` | `EventChannel<Packet<?>>` | Cancelable, Args: `Connection` | `packetPoint` 的接收侧子通道 |
| `getPacketSendPoint()` | `EventChannel<Packet<?>>` | Cancelable, Args: `Connection` | `packetPoint` 的发送侧子通道 |

**推荐使用精确通道**:`getPacketPoint().getChannel(XXX.class)`,
避免用 `getPacketSendPoint()` / `getPacketAcceptPoint()`(会收到所有包,性能差且容易出错)。

```java
registerListener(Listener.getPacketPoint().getChannel(ServerboundUseItemOnPacket.class), this::onUseItemOn);
registerListener(Listener.getPacketPreHandlePoint().getChannel(ClientboundBlockUpdatePacket.class), this::onBlockUpdate);
registerListener(Listener.getPacketPostHandlePoint().getChannel(ClientboundDisconnectPacket.class), this::onDisconnect);
```
