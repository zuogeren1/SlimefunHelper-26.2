# SlimefunHelper 模块开发速查

> 对应代码:`src/main/java/me/matl114/hacks/api/BaseModule.java`
> 版本:**Minecraft 26.1.2 / 26.2**(mojmap 官方名)。模块系统本身两版一致。

## 0. 统一注册管理(核心原则)

**所有事件监听、命令注册、热键绑定都必须通过 `BaseModule` 提供的注册方法完成**,
这样模块被移除时(`onRemove()`)才能自动清理,避免重复注册和内存泄漏。

| 注册内容 | 推荐方法 | 说明 |
|---------|----------|------|
| 事件监听 | `registerListener(ListenerPoint, Consumer)` | 自动绑定模块生命周期 |
| 命令树 | `registerCommandBootstrap(Consumer<MainCommand>)` | 在 `registerAll()` 里构建命令 |
| 整体命令 | `registerCommand(Supplier<AbstractMainCommand>)` | 等价于上一行的常用封装 |
| 子命令形式 | `registerAsSubCommand(String, Supplier<AbstractMainCommand>)` | 挂到同名分发名底下 |
| 配置热键 | `hotkey()` / `toggleHotkey()` / `moduleEntry()` 构建器 | 自动注册到输入系统 |
| 任务调度 | `Tasks.scheduleXxx()` | **不随模块自动取消**,需自己停止 |

**禁止直接调用**:

- `Listener.registerPacketListener` / `Listener.registerSinglePacketListener` 等静态注册方法
  —— 它们没有 owner 记录,`onRemove()` 时清理不掉
- `MainCommand.registerCommandBootstrap` 而不经过 `BaseModule.registerCommandBootstrap`
- `SimpleInputManager.getInstance().registerHotKeys` 绕过 `BaseModule`

## 1. 模块基础骨架

```java
package me.matl114.hacks.modules.move;

import me.matl114.hacks.api.BaseModule;
import me.matl114.hacks.api.ModulePath;
import me.matl114.managers.Configs;
import me.matl114.managers.config.FlagRef;
import me.matl114.managers.config.IntRef;
import me.matl114.managers.config.KeyBindRef;
import me.matl114.managers.input.MultiKeyBind;

public class MoveTimer extends BaseModule {
    // ModulePath = (Config, String[]) 的组合,替代旧的裸 String[] 路径
    public final ModulePath moveSpeed = makePath(Configs.MOV_CONFIG, "move-speed");
    public final ModulePath moveTimer = moveSpeed.add("timer");

    public MoveTimer() {
        super("MoveTimer");          // 必须传模块名
        bindFlag(enable);            // 把模块启用状态绑到这个 Flag
    }

    public final FlagRef enable = flagBuilder(moveTimer.add("timer-enable")).build();

    public final KeyBindRef keyBind =
            moduleEntry(moveTimer.add("timer-enable-hotkey"), new MultiKeyBind(), moveTimer.add("timer-enable"))
                    .build();

    public final IntRef timer = builder(moveTimer.add("multiply"), IntRef.TYPE)
            .defaultValue(0)
            .validator(Configs.INT_NONNEGATIVE)
            .build();

    @Override
    public void registerAll() {
        super.registerAll();
        // 事件 / 命令在这里统一注册
    }

    @Override
    public void onEnableModule() {}

    @Override
    public void onDisableModule() {}
}
```

要点:

- 构造函数**必须** `super("模块名")`,这个名字是 GUI 与 `ModuleManager.getModule(name)` 的索引。
- 初始化顺序:先 `super("...")`,再按**书写顺序**跑所有实例字段初始化,最后才跑构造函数体。
  所以构造函数体里的 `bindFlag(enable)` 拿到的已经是建好的 Ref。
  反过来说,字段之间互相引用时被引用者必须**写在前面**(上面的 `moveTimer` 就写在 `enable` 之前)。
- 若类里声明了 `public static X INSTANCE;`(非 final、类型就是自己),
  基类构造函数会自动把 `this` 塞进去,不用手写赋值。

## 2. 把模块注册进分组

模块本身不会自己挂到游戏里,必须由所在分组的 `*Tasks.java` 注册:

```java
// 以 MineTasks 为例
public static final ModuleGroup moduleGroup = new ModuleGroup("Mine");

private static void initModules(ModuleManager m) {
    mineExtra = new MineExtra().register(m);   // register() 返回 this,方便直接赋值
    mineBot = new MineBot().register(m);
}

static {
    moduleGroup.registerFactories(MineTasks::initModules);  // 只是登记初始化函数
    HackModules.registerModuleGroup(moduleGroup);
}
```

- `module.register(m)` == `m.registerModule(module)` + 记录 manager,并触发 `onCreate()`(内部调 `registerAll()`)。
- `registerFactories` 登记的是"怎么建模块",真正的实例化发生在 `loadModules()` / 重载时。

## 3. 配置类型(Ref)

所有配置项都是 `me.matl114.managers.config` 下的 `Ref`,通过构建器创建并 `build()`:

| 类型 | 构建示例 |
|------|----------|
| `FlagRef` | `FlagRef ref = flagBuilder(path).build();` |
| `IntRef` | `builder(path, IntRef.TYPE).defaultValue(1).build()` |
| `DoubleRef` | `builder(path, DoubleRef.TYPE).defaultValue(1.0).build()` |
| `FloatRef` | `builder(path, FloatRef.TYPE).defaultValue(1.0f).build()` |
| `LongRef` | `builder(path, LongRef.TYPE).defaultValue(0L).build()` |
| `StringRef` | `builder(path, StringRef.TYPE).defaultValue("").build()` |
| `EnumRef<E>` | `builder(path, E.class).defaultValue(E.VAL).build()`(E 是 `ConfigEnum`) |
| `KeyBindRef` | `hotkey(path).defaultValue(new MultiKeyBind(...)).registerHotkey(...).build()` |
| `ListRef` | `builder(path, ListRef.TYPE).build()` |
| `MapRef` | `builder(path, MapRef.TYPE).build()` |
| `NBTRef<E>` | `builder(path, E.class).defaultValue(...).build()`;泛型类型用 `X.<A,B>parameter()` |

便捷入口(都是 `BaseModule` 上的方法):

```java
flagBuilder(ModulePath)                     // Boolean,默认 false
intBuilder(ModulePath)                      // IntRef
doubleBuilder(ModulePath)                   // DoubleRef
builder(ModulePath, Class<T> type)          // 泛型入口
builder(Config, String[] path, Class<T>)    // 旧式裸路径入口
hotkey(ModulePath)                          // MultiKeyBind
hotkey(ModulePath, MultiKeyBind defaultVal)
toggleHotkey(ModulePath path, MultiKeyBind def, ModulePath togglePath)   // 按下即切换某个 flag
moduleEntry(ModulePath hotkeyPath, MultiKeyBind def, ModulePath togglePath)
moduleEntry(..., Supplier<Component> descriptor)                          // 带自定义描述的模块入口
toggleConfigHotkey(Config, String[] path, MultiKeyBind def)
```

构建器链式方法(`BaseModule.WrapperSettingBuilder`):

| 方法 | 说明 |
|------|------|
| `.defaultValue(V)` | 默认值 |
| `.validator(Predicate<V>)` | 值校验器,随模块生命周期注销 |
| `.listValidator(Predicate<String>)` | 仅 `ListRef`,逐元素校验 |
| `.updateListener(Consumer<V>)` | 值更新回调,随模块生命周期注销 |
| `.registerHotkey(SimpleHotKey.InputHandler)` | 把热键处理函数挂上 |
| `.hideConfig()` / `.showConfig()` / `.show(BooleanSupplier)` / `.experimental()` | 控制配置界面显示 |
| `.apply(Consumer<Ref>)` | 拿到裸 Ref 再加工 |
| `.build()` | 产出 Ref 并完成注册 |

> `flagBuilder` 内部已经给了 `defaultValue(false)`,不要再传默认值。

## 4. NBTRef(复杂数据结构)

`NBTRef<E extends NBTParsable>` 用来存复杂配置:每个 `NBTParsable` 与一个 `NBTType` 绑定,
`NBTType` 实现了自己的 Codec、`StringifyFactory` 与 `WidgetFactory`,
所以配置界面上的编辑控件也是由它生成的。

常用 `NBTParsable`:

```java
new Regex("regexString");
new RegistryRegex(new Regex("..."), Registries.ITEM);
new WrapColor(TextColor.fromRgb(...));
new EntryPrimitiveMap<T, W>(Registry<T>, NBTType<W>, Map<T, W> map);
new PrimitiveList<W>(NBTType<W> type, List<W> list);
```

基础类型(如 `Integer` / `String`)本身不是 `NBTParsable`,但它们的 `NBTType` 会被登记进
`NBTTypes.PRIMITIVE_TYPES`,可以直接 `primitiveTypes("int")` 取用:

```java
// interface me.matl114.hacks.utils.config.NBTTypes
public NBTType<Integer> INT_TYPE;
public NBTType<Double> DOUBLE_TYPE;
public NBTType<Boolean> BOOLEAN_TYPE;
public NBTType<String> STRING_TYPE;
public NBTType<TextColor> COLOR_TYPE;
public NBTType<Registry<?>> REGISTRY_TYPE;
public NBTType<Pattern> REGEX_TYPE;
public NBTType<Identifier> IDENTIFIER_TYPE;
public NBTType<Tag> NBT_ELEMENT_TYPE;
public NBTType<CompoundTag> NBT_COMPOUND_TYPE;

public static Map<String, NBTType<?>> PRIMITIVE_TYPES = new LinkedHashMap<>();

public static <T> NBTType<T> primitiveTypes(String string) {
    return (NBTType<T>) PRIMITIVE_TYPES.get(string);
}

public static Codec<NBTType<?>> CODEC = Codec.STRING.flatXmap(
        s -> {
            var nbtType = primitiveTypes(s);
            return nbtType == null ? DataResult.error(() -> "Not found") : DataResult.success(nbtType);
        },
        t -> {
            if (PRIMITIVE_TYPES.containsKey(t.typeName())) {
                return DataResult.success(t.typeName());
            } else {
                return DataResult.error(() -> "Not a primitive type: " + t.typeName());
            }
        });
```

> 注意形态:上面这些字段是 **实例字段**(通过 `NBTTypes` 的实例访问),不是 `static` 的。
> 注意名字:mojmap 里 `NbtElement` → `Tag`,`NbtCompound` → `CompoundTag`,`Identifier` 也不再叫 `ResourceLocation`。

## 5. 事件监听

事件只需要在 `registerAll()` 里注册**一次**,模块禁用时不要重复注册,移除时框架会自动注销。

```java
@Override
public void registerAll() {
    super.registerAll();

    // 基础事件
    registerListener(Listener.getPostGameTick(), this::onTick);
    registerListener(Listener.getAttackAction(), this::onAttack);
    registerListener(RenderListener.getRender3DEvent(), this::onRenderWorld);

    // 精确网络包事件(不要用 getPacketSendPoint / getPacketAcceptPoint 收全量包)
    registerListener(Listener.getPacketPoint().getChannel(ServerboundInteractPacket.class), this::onInteract);
    registerListener(Listener.getPacketPreHandlePoint().getChannel(ClientboundBlockUpdatePacket.class), this::onBlockUpdate);
    registerListener(Listener.getPacketPostHandlePoint().getChannel(ClientboundDisconnectPacket.class), this::onDisconnect);

    // 带优先级(数值越大越先执行)
    registerListener(Listener.getAttackAction(), this::onAttackWithPriority, -999);
}
```

- 通道通过 `Listener.getXxx()` / `RenderListener.getXxx()` 获取,**不要直接访问静态字段**。
- 处理器签名是 `Consumer<Event<T>>` 或 `Predicate<Event<T>>`(`Predicate` 返回 false 等价于 cancel)。
- `Event` 的成员:`context()` / `context(T)` / `isCancelled()` / `cancel()` / `getArgs(int)`,
  以及只读公有字段 `canCancel` / `canModifyContext`(**是字段,不是方法**)。
  不允许取消/修改时调用 `cancel()` / `context(v)` 会抛 `IllegalArgumentException`。

> 通道总表见 `事件.md`。

## 6. 任务调度

```java
Tasks.scheduleDelayed(() -> {}, 20);                 // 20 tick 后跑一次
Tasks.scheduleRepeated(() -> false, 10, 5);          // 10 tick 后开始,每 5 tick 一次,返回 true 停止
Tasks.scheduleTask(new RepeatTask(20, 2) {
    @Override
    public boolean runTask() {
        return false;                                 // true = 结束
    }
});
Tasks.scheduleTaskPre(...);                          // Pre 系列在 tick 前执行
```

- 全部跑在游戏 tick 上,**不是独立线程**。
- `Tasks` 没有 `cancelTask`:要提前停止就自己留住 `RepeatTask` 引用调 `cancel()`,
  或者让 `BooleanSupplier` 返回 `true`;模块 `onDisableModule()` 里别忘了处理。

## 7. 命令注册

```java
@Override
public void registerAll() {
    super.registerAll();
    registerCommandBootstrap(this::bootStrapTravelCommand);
}

public void bootStrapTravelCommand(MainCommand mainCommand) {
    TreeSubCommand main = mainCommand.mainBuilder().name("travel").build();
    main.subBuilder(SubCommand.taskBuilder())
            .name("to")
            .helper("message.command.travel.to.help")
            .arg(SimpleCommandArgs.argumentBuilder(MovTasks.TpaAndPosArgumentType::new)
                    .name("target")
                    .build())
            .post(e -> e.executor(this::onTravelTo))
            .complete();
}
```

- `mainBuilder()` 创建一级树命令并自动挂到根;`subBuilder(...)` 创建下级命令,`complete()` 完成注册。
- `.name()` 是命令构建器的方法;参数构建器上的 `.name()` 来自 Lombok `@Setter(fluent)`,同样是命名参数。
- `.post(e -> e.executor(...))` 里的 `e` 是 `TaskSubCommand`,`executor` 是它的 fluent setter,
  接受一个 `CommandContext`(函数式接口)。

> 完整 DSL 见 `命令.md`。

## 10. 生命周期

| 方法 | 时机 | 说明 |
|------|------|------|
| 构造器 | 实例化 | `super(name)`、`bindFlag(...)` |
| `onCreate()` | `ModuleManager.registerModule` 时 | 基类默认实现就是调 `registerAll()` |
| `registerAll()` | 由 `onCreate()` 调用 | 在这里注册事件/命令 |
| `onEnableModule()` | 绑定的 Flag 变 true | 重置运行时状态 |
| `onDisableModule()` | 绑定的 Flag 变 false | 清理运行时状态、停掉自己的任务 |
| `onRemove()` | `unregisterModule` 时 | 自动注销监听器/配置回调/热键/命令 |

`onRemove()` 里会调用 `unregisterAll()`,它按 owner 反注册:
事件处理器、配置 validator / updateListener、list elementValidator、热键(置空 handler)、命令 bootstrap。
所以**只注册、不手动反注册**是正确姿势。

## 11. MovementModifier 注册(玩家移动管道)

要让模块介入玩家移动(鞘翅飞行增强、速度调整、stepheight 等),
实现 `LegalMovementManager.MovementModifier`,再通过 `DelegateMovementModifier` 挂进管道。

### 11.1 接口方法

| 方法 | 调用时机 | 用途 |
|------|----------|------|
| `applyPreTickModify(Event<LegalMovementManager>)` | 玩家 tick 开始前 | 初始化 / 重置每 tick 状态 |
| `applyAfterInputTick(Event<LegalMovementManager>)` | 输入处理之后 | 基于原始输入做修改(如速度调整) |
| `applyBeforeTravelTick(Event<LegalMovementManager>, Event<Vec3>)` | `travel` 之前 | 修改即将交给物理引擎的移动向量 |
| `applyAfterTravelTick(Event<LegalMovementManager>, Event<Vec3>)` | `travel` 之后 | 对物理结算结果做后处理 |
| `applyBeforeInputPacketModify(Event<LegalMovementManager>)` | 输入包发送前 | 修改即将发送的输入包 |
| `applyBeforeMovementPacketModify(Event<LegalMovementManager>)` | 移动包发送前 | 修改位置/动作包(高级) |
| `postModify(Event<LegalMovementManager>, boolean)` | 玩家 tick 结束后 | 清理;返回 `false` 会让该 modifier 被移除 |

另外还有 `priority()` 与 `shouldApply(Event<LegalMovementManager>)` 控制是否参与本 tick。

### 11.2 管道

| 常量 | 状态 | 说明 |
|------|------|------|
| `MovTasks.PLAYER_PIPELINE_0` | **启用中** | 通用监听/修改管道(priority 0) |
| `MovTasks.PLAYER_PIPELINE_ROT` | 已注释 | 曾经用于"只改 rot 不改 pos" |
| `MovTasks.PLAYER_PIPELINE_POS` | 已注释 | 曾经用于"只改 pos 不改 rot" |

> 现在只有 `PLAYER_PIPELINE_0` 被真正 `addMovementModifier` 进 `LegalMovementManager`。
> 需要"只改位置"或"只改朝向"的效果,要自己在 `applyBeforeTravelTick` 等回调里区分处理。

### 11.3 注册示例

```java
public static LegalMovementManager.DelegateMovementModifier instance;

public ElytraFlightLegit() {
    super("ElytraFlightLegit");
    bindFlag(enable);
    if (instance == null) {
        instance = new LegalMovementManager.DelegateMovementModifier(this::cast);
        MovTasks.PLAYER_PIPELINE_0.addMovementModifierFactory(() -> instance);
    }
    instance.setDelegate(this::cast);
}
```

注意:

- `DelegateMovementModifier` 的构造参数是"返回 `MovementModifier` 实例的 `Supplier`"。
- `setDelegate(Supplier)` 可以动态切换真正生效的实现,`DelegateMovementModifier` 的每个回调都会转调当前 delegate。
  注意 `MovementModifier` 的方法**全部是 default**,它不是函数式接口,**不能用 lambda** 当空实现;
  要"关掉"就地写一个匿名类,或者让 delegate 的 `shouldApply` 返回 false、`postModify` 返回 false。
- 必须在管道里注册,否则接口方法根本不会被调用。
- 不需要手动移除管道里的 modifier:同类型模块下次创建时会顶替上一个。

## 12. 完整示例

```java
public class AutoJump extends BaseModule {
    public static final ModulePath PATH = makePath(Configs.MOV_CONFIG, "auto-jump");

    public AutoJump() {
        super("AutoJump");
        bindFlag(enable);
    }

    public final FlagRef enable = flagBuilder(PATH.addEnable()).build();

    public final KeyBindRef hotkey =
            toggleHotkey(PATH.addHotkey(), new MultiKeyBind(KeyCode.KEY_J), PATH.addEnable()).build();

    public final IntRef interval = builder(PATH.add("interval"), IntRef.TYPE)
            .defaultValue(5)
            .validator(Configs.INT_POSITIVE)
            .build();

    private int counter;

    @Override
    public void onEnableModule() {
        counter = 0;
    }

    @Override
    public void onDisableModule() {
        counter = 0;
    }

    @Override
    public void registerAll() {
        super.registerAll();
        registerListener(Listener.getPostGameTick(), this::onTick);
    }

    private void onTick(Event<LocalPlayer> event) {
        if (!enable.get() || checkNull()) return;
        if (mc.player.onGround()) {
            if (++counter >= interval.get()) {
                mc.player.jumpFromGround();
                counter = 0;
            }
        } else {
            counter = 0;
        }
    }
}
```

## 13. 常见错误

- ❌ 构造函数不写 `super("Name")` → 模块名缺失,GUI 与查找都会出问题
- ❌ 直接访问 `Listener.postGameTick` / `RenderListener.renderLayerTasks` → 必须用 `getXxx()`
- ❌ 直接调 `Listener.registerSinglePacketListener` → 换成 `registerListener(Listener.getPacketPoint().getChannel(X.class), ...)`
- ❌ 用 `getPacketSendPoint()` / `getPacketAcceptPoint()` 监听全量包 → 性能差且容易出错
- ❌ 在 `registerAll()` 之外注册命令 → 必须放进去
- ❌ 手搓 `SimpleHotKey` 再塞给 `SimpleInputManager` → 用 `hotkey()` / `toggleHotkey()` / `moduleEntry()` 构建器
- ❌ 在 `onEnableModule()` 里重复注册事件 → 事件只在 `registerAll()` 注册一次
- ❌ 以为 `registerHotkey` 的 lambda 是 `(action, pressed)` → 实际是 `boolean handle(IHotKey, IInputManager)`
- ❌ 以为 `Tasks` 有 `cancelTask` → 自己留引用或让 `BooleanSupplier` 返回 true
- ❌ 直接用 `mc.player.jump()` → mojmap 里是 `jumpFromGround()`
- ❌ 未检查 `canCancel` / `canModifyContext` 就调 `cancel()` / `context(v)` → 会抛异常,必要时先看字段
- ❌ 在 `onDisableModule()` 里忘了停自己开的子线程 / 定时任务
